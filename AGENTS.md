# Работа в репозитории

## Окружение

Используйте mise. Установка и запуск описаны в [README.md](README.md), задачи и версии инструментов — в `mise.toml`.
Локальные переопределения и секреты храните в игнорируемом `mise.local.toml`.
При смене порта фонового процесса обновляйте его `ready_port`.

## Код и API

- Сервер — `server/`, интерфейс на Mantine — `web/`, тесты Vitest — `tests/*.test.ts`, скрипты — `scripts/`.
- API изменяйте в `api/main.tsp`, затем запускайте `mise run generate`. Коммитьте результаты из `generated/`; вручную их не редактируйте. Фронтенд обращается к API через сгенерированный SDK.
- При обновлении инструментов проверяйте цепочку TypeSpec → OpenAPI → SDK, сервер и сборку фронтенда.
- Добавляйте тесты для новой функциональности и регрессий. Тесты с запуском приложения должны иметь таймауты и завершать процессы при ошибке.
- Перед PR запускайте `mise run check`. Новые проверки включайте в эту задачу; CI вызывает её же. Сохраняйте строгость TypeScript и линтера. Учебный `.github/workflows/hexlet-check.yml` не изменяйте.
- Git-хуки настраивайте через hk. Сообщения коммитов — Conventional Commits по `commitlint.config.cjs`; в заголовке реализации указывайте тикет: `feat: запись на свободный слот (#12)`.
- При изменении поведения или настройки обновляйте README. Статус работ и результаты прогонов сообщайте в отчёте, а не в этом файле.

## Workflow и контекст

Завершив запрошенный этап, представьте результат для ревью и остановитесь. Следующий этап начинайте по отдельному указанию; явно запрошенную последовательность этапов выполняйте без повторных подтверждений.

- Перед подготовкой спецификаций, публикацией задач и реализацией читайте [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md): этапы, артефакты и отчёты о проверках и приёмке. Трекер — GitHub Issues `lukyanzhukov/ai-for-developers-project-386`.
- При разборе задач используйте метки из [docs/agents/triage-labels.md](docs/agents/triage-labels.md).
- Перед изучением предметной области читайте [GLOSSARY.md](GLOSSARY.md), относящиеся к задаче решения в `docs/adr/` и [правила работы с ними](docs/agents/domain.md).
