# Календарь звонков

[![hexlet-check](https://github.com/lukyanzhukov/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/lukyanzhukov/ai-for-developers-project-386/actions)

Сервис записи на встречи с одним владельцем календаря. Учебный проект [Хекслета](https://ru.hexlet.io/programs/ai-for-developers) по мотивам [Cal.com](https://cal.com/).
[Исходное задание](https://files.hexlet.app/a/2ipc5m).

## Сценарий записи на звонок

1. Владелец создаёт тип встречи в `/admin`: название, описание и длительность от 1 до 1440 минут. ID можно задать вручную или оставить автоматическим.
2. Гость открывает `/booking`, выбирает тип встречи, дату и свободное время, вводит имя и email. Заметка необязательна.
3. После подтверждения гость видит детали записи. Занятое время становится недоступно для всех типов встреч.
4. Владелец просматривает текущие и будущие встречи в `/admin?view=bookings`. Список обновляется при открытии и кнопкой «Обновить».

## Правила и ограничения

- Окно записи — сегодня и следующие 13 календарных дней в `Asia/Novokuznetsk`. Рабочее время: Пн–Пт, 09:00–18:00, начало слотов каждые 15 минут. Праздники и перерывы не учитываются.
- Встреча целиком помещается в рабочее время и начинается строго позже текущего времени сервера. Пересечения запрещены; следующая встреча может начаться сразу после предыдущей.
- Сервер повторно проверяет доступность при подтверждении. Из двух конфликтующих запросов успешен один. Повтор с тем же ключом и данными возвращает сохранённую запись.
- **Данные хранятся в памяти одного процесса и теряются при перезапуске или деплое.** Запускайте один экземпляр сервера.
- **Авторизации нет: админка и контактные данные гостей доступны всем.** Используйте вымышленные персональные данные.
- Нет редактирования и удаления типов, отмены и переноса встреч, email-уведомлений, интеграций с календарями и видеозвонками.

## Локальный запуск

Установите [mise](https://mise.jdx.dev/getting-started.html), затем:

```bash
git clone https://github.com/lukyanzhukov/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise trust
mise install
mise run dev
```

`mise install` устанавливает инструменты и через хук `postinstall` запускает `mise run install`: зависимости по lockfile, Chromium для тестов и Git-хуки hk. После обновления зависимостей повторите `mise run install`. На Linux установка системных библиотек Chromium может потребовать sudo.

Интерфейс: <http://127.0.0.1:5173>, API: <http://127.0.0.1:3000>. Vite проксирует `/api` на сервер.

```bash
mise run status   # состояние фоновых серверов
mise run logs     # логи
mise run stop     # остановка
```

`HOST`, `PORT` и `WEB_PORT` заданы в `mise.toml`. Локальные переопределения храните в игнорируемом `mise.local.toml`; при смене портов обновляйте `ready_port` процессов.

Собранное приложение отдаёт интерфейс и API с одного адреса:

```bash
mise run build
mise run start    # http://127.0.0.1:3000, остановка Ctrl+C
```

## Разработка

### Макет списка владельца (временная ветка)

`mise run prototype` → <http://127.0.0.1:5174/admin?view=bookings&prototype=1&variant=A>.
Варианты A (карточки по датам), B (таблица), C (лента) переключаются нижней панелью и стрелками клавиатуры вне элементов управления. По умолчанию открыт полный список; «Календарь» открывает календарь и сохраняет выбранную дату при переключении режимов. Данные вымышленные, время зафиксировано на 9 ноября 2026, 10:15 Asia/Novokuznetsk. Есть текущая встреча и запись за пределами 14 дней, пустое состояние, загрузка и ошибка обновления с сохранёнными данными. Кнопка обновления демонстрационная. Макет доступен только в dev; это материал для ревью до спецификации, а не реализация задачи.

TypeScript, Node.js, Fastify; React, Vite и Mantine. Версии инструментов — в `mise.toml`, зависимости — в `package.json` и `pnpm-lock.yaml`.

- `server/` — сервер и хранение данных в памяти.
- `web/` — интерфейс.
- `api/main.tsp` — контракт TypeSpec.
- `generated/` — OpenAPI, Fetch SDK, серверные типы и JSON Schema.
- `tests/` — тесты Vitest, HTTP-проверки через SDK и браузерные сценарии Playwright.
- `scripts/` — генерация и проверки коммитов и деплоя.
- `GLOSSARY.md`, `docs/adr/` — термины и решения; `AGENTS.md` — инструкции для агентов.

Цикл разработки и артефакты описаны в [правилах трекера](docs/agents/issue-tracker.md#workflow-and-artifacts). При разборе идеи агент предлагает, стоит ли проверить её на макетах до спецификации. Этот этап включается только по вашему явному согласию: макеты проходят итерации ревью и приёмку, затем согласованный дизайн учитывается в спецификации и GitHub-задачах.

### API

| Метод | Путь                                   | Назначение                               |
| ----- | -------------------------------------- | ---------------------------------------- |
| GET   | `/api/health`                          | Проверка готовности: `{"status":"ok"}`   |
| GET   | `/api/meeting-types`                   | Список типов встреч                      |
| POST  | `/api/meeting-types`                   | Создание типа встречи                    |
| GET   | `/api/meeting-types/{id}/availability` | Свободные слоты                          |
| POST  | `/api/bookings`                        | Подтверждение записи с `Idempotency-Key` |
| GET   | `/api/bookings`                        | Будущие и текущие встречи всех типов     |

Поля, ограничения и ответы описаны в [api/main.tsp](api/main.tsp). Даты календаря относятся к часовому поясу владельца, моменты начала и окончания передаются в UTC.

После изменения контракта выполните `mise run generate` и закоммитьте `generated/`. Эти файлы не редактируют вручную. `mise run check` повторяет генерацию и выявляет расхождения, оставляя обновлённые файлы для проверки.

Маршруты Fastify зарегистрированы вручную: генератор Hey API выпускает типы обработчиков и схемы, но не регистрацию маршрутов.

### Проверки и коммиты

```bash
mise run check          # генерация, линтер, форматирование, workflow, типы, тесты и коммиты
mise run test           # сборка и Vitest, включая Chromium
mise run lint
mise run format:check
mise run typecheck
mise run fix            # автоисправления и форматирование
```

hk проверяет изменённые файлы перед коммитом, commitlint — сообщение коммита, полный `check` выполняется перед push и в CI. Формат сообщений — Conventional Commits, например `feat: запись на свободный слот (#12)`.
Учебный `.github/workflows/hexlet-check.yml` и имя репозитория сохраняйте без изменений.

### Выпуски

После push в `main` workflow `release-please.yml` готовит release-PR с версией и `CHANGELOG.md`. После его слияния создаёт тег и GitHub Release. Публикации в npm и деплоя в этом workflow нет.

В Settings → Actions → General включите **Allow GitHub Actions to create and approve pull requests**. Используется встроенный `GITHUB_TOKEN`.
Созданный им release-PR не запускает CI автоматически: перед слиянием выполните `mise run check` на его ветке.

## Docker и Render

[Публичный сервис](https://call-calendar-386-o6lw.onrender.com).

Если сервис не открывается из РФ, попробуйте VPN: доступность может зависеть от провайдера и маршрута. Причина сетевых таймаутов при проверке не установлена; необходимость VPN — предположение.

```bash
docker build -t call-calendar:production .
docker run --rm --name call-calendar -e PORT=8080 -p 8080:8080 call-calendar:production
```

Адрес: <http://localhost:8080>. Контейнер слушает `0.0.0.0`, порт задаётся через `PORT` (по умолчанию 3000). Проверка готовности — `/api/health`. Остановка: `docker stop call-calendar`.

Для Render используйте Dockerfile из корня, один экземпляр и проверку `/api/health`. У сервиса с публичным Git URL после push нужно отдельно запустить деплой; для автоматического деплоя подключите репозиторий через Git provider credentials. Проверяйте SHA коммита и статус `live`.

Адрес MCP задан в `.codex/config.toml`. Для подключения выполните `codex mcp login render`, завершите OAuth и перезапустите сессию агента. Секреты храните вне Git.

Проверка работающего сервиса:

```bash
DEPLOYMENT_URL=https://call-calendar-386-o6lw.onrender.com mise run deployment:check
```

Команда проверяет создание типа, запись гостя, отказ при конфликте и список владельца. Она добавляет синтетические данные; нужен свободный слот в ближайшие 14 дней.
